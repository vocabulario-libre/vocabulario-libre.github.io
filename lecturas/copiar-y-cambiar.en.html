Copy and change

The folder

The whole work is this folder: 15 reading editions with their sources, the vocabulary trainer with its data, the documents that govern them, and the programs that build and check them. README.md lists the files. The authors’ texts are public domain; everything added is CC0 (LICENSE): the folder is copied, hosted and changed without condition.

What is being made now and what comes after: Upcoming changes.

How it is had

From the site, file by file: the folder lecturas/. Whole, from the repository of the mirror, https://github.com/vocabulario-libre/vocabulario-libre.github.io: as one archive,

https://github.com/vocabulario-libre/vocabulario-libre.github.io/archive/refs/heads/main.zip

or by a clone,

git clone -c core.autocrlf=false https://github.com/vocabulario-libre/vocabulario-libre.github.io

The folder is lecturas/ inside either. -c core.autocrlf=false keeps the files as published; without it, git on Windows rewrites line endings by default, and the check reports the files as changed. To verify the folder: sha256sum -c MANIFEST.sha256 inside it, or python check_folder.py.

How it is changed

The .md file of an edition is its source; its PDF and its EPUB are built from it. The trainer is built from the editions and from the files of glosses and definitions of each, vocab/NN/. README.md gives the commands; they need Python 3.9 or later, reportlab and pyphen. After a change: rebuild, then check.

To correct a word in an edition — here, edition 12:

  1. Edit its source, 12-maximas-para-mi-hija-lectura.md.
  2. Rebuild its files: python build_pdf.py 12, then python build_epub.py 12.
  3. Run python check_folder.py. It ends on FOLDER CHECK PASS.

To change the English equivalent of a word:

  1. Edit the edition’s file of equivalents, vocab/12/glosses.json.
  2. Rebuild the trainer: in vocab/, python extract_vocab.py, then python build_app.py.
  3. Rebuild the main pages, which carry cards from the trainer: back in the folder, python build_index.py.
  4. Run python check_folder.py, as above.

The folder can be given whole to a language model: the archive unpacked, or the clone, and an instruction that ends at the check. Three instructions:

  • «In edition 12, in the notes on the sources, replace this word with this one. Rebuild the edition’s PDF and EPUB. Run check_folder.py and give its last line.»
  • «In vocab/12/glosses.json, change the gloss of this word to this. Rebuild the trainer, then the main pages. Run check_folder.py and give its last line.»
  • «Run check_folder.py. List what has changed in this folder since the release and what is out of date.»

What is checked

check_folder.py compares every file with MANIFEST.sha256 and names what has changed since the release. It rebuilds every file the folder’s programs build — the PDFs and EPUBs of the editions and the documents, the trainer, the main pages and these pages — and names each that is out of date with its source. The primers and the font are held to the manifest alone. It runs the checks of counts and of spelling. It runs anon.py, which names any file that carries a person’s name or address, or a trace of the machine it was made on: a path, a user’s name, a time zone. Its last line is FOLDER CHECK PASS, or FOLDER CHECK FAIL and what failed.

It does not check the rest of the standard. compliance.py, drift.py and release.py check the editions against the policy; they need the working files the editions were made from, which are not in this folder. A new edition, or a change to an apparatus, is not checked here against the policy. MANIFEST.sha256 and PROVENANCE.md describe the release, not a changed copy.
